# Audio Processing Binaries

This directory contains command-line tools for audio processing, transcription, and performance profiling.

## Requirements

- **Rust toolchain** - For building the binaries
- **ffmpeg** (optional) - Required only for MP3/FLAC generation with `generate-test-audio`
  - Install on Ubuntu/Debian: `sudo apt install ffmpeg`
  - Install on macOS: `brew install ffmpeg`
  - Install on Arch: `sudo pacman -S ffmpeg`

## Available Binaries

### 1. `audio-trim`
Trim audio files to a specific time range.

**Usage:**
```bash
cargo run --release --bin audio-trim -- \
  --input input.mp3 \
  --output output.wav \
  --start 5.0 \
  --end 10.0
```

**Arguments:**
- `--input, -i` - Input audio file (MP3, WAV, FLAC, etc.)
- `--output, -o` - Output WAV file path
- `--start, -s` - Start time in seconds
- `--end, -e` - End time in seconds
- `--verbose, -v` - Show detailed information

**Example:**
```bash
# Trim a sermon from 2:30 to 45:00
cargo run --release --bin audio-trim -- \
  -i sermon.mp3 \
  -o trimmed_sermon.wav \
  -s 150.0 \
  -e 2700.0
```

### 2. `generate-test-audio`
Generate test audio files in WAV, MP3, or FLAC format for benchmarking and profiling.

**Usage:**
```bash
cargo run --release --bin generate-test-audio -- \
  --output test.wav \
  --duration 60 \
  --sample-rate 44100 \
  --channels 2 \
  --bits 16 \
  --frequency 440
```

**Arguments:**
- `--output, -o` - Output file path (supports .wav, .mp3, .flac extensions)
- `--duration, -d` - Duration in seconds (default: 60)
- `--sample-rate, -s` - Sample rate in Hz (default: 44100)
- `--channels, -c` - Number of channels (1=mono, 2=stereo, default: 2)
- `--bits, -b` - Bit depth (16 or 32, only for WAV output, default: 16)
- `--frequency, -f` - Test tone frequency in Hz (default: 440)
- `--mp3-bitrate` - MP3 bitrate in kbps (default: 320)

**How it works:**
- WAV files are generated directly
- MP3 and FLAC files are generated by first creating a WAV, then converting with ffmpeg
- Requires ffmpeg to be installed for MP3/FLAC generation

**Examples:**
```bash
# Generate 5-minute WAV file (16-bit stereo)
cargo run --release --bin generate-test-audio -- \
  -o test_5min.wav -d 300 -s 44100 -c 2 -b 16

# Generate 1-minute 32-bit float WAV file
cargo run --release --bin generate-test-audio -- \
  -o test_float.wav -d 60 -s 48000 -c 2 -b 32

# Generate 5-minute MP3 file at 320 kbps
cargo run --release --bin generate-test-audio -- \
  -o test_5min.mp3 -d 300 --mp3-bitrate 320

# Generate 5-minute MP3 file at 128 kbps
cargo run --release --bin generate-test-audio -- \
  -o test_5min_128k.mp3 -d 300 --mp3-bitrate 128

# Generate 5-minute FLAC file (lossless)
cargo run --release --bin generate-test-audio -- \
  -o test_5min.flac -d 300 -s 44100 -c 2
```

### 3. `profile-trim`
Benchmark audio trimming performance with averaged results.

**Usage:**
```bash
cargo run --release --bin profile-trim -- \
  --input input.wav \
  --output output.wav \
  --start 10.0 \
  --end 20.0 \
  --iterations 5
```

**Arguments:**
- `--input, -i` - Input audio file
- `--output, -o` - Output WAV file
- `--start, -s` - Start time in seconds (default: 10.0)
- `--end, -e` - End time in seconds (default: 20.0)
- `--iterations` - Number of iterations to average (default: 5)

**Output:**
- Time per iteration
- Throughput (MB/s)
- Average, min, max times
- Standard deviation
- Realtime factor (how many times faster than realtime)

**Example:**
```bash
# Profile trimming a large MP3 file
cargo run --release --bin profile-trim -- \
  -i sermon.mp3 \
  -o test_output.wav \
  -s 100.0 \
  -e 200.0 \
  --iterations 10
```

Detailed performance breakdown for WAV file trimming.

**Usage:**
```bash

  --end 20.0
```

- `--start, -s` - Start time in seconds (default: 10.0)

**Output:**

3. Get track info

### 6. `transcribe`
Transcribe audio files using Whisper speech recognition.

**Note:** This binary supports GPU acceleration via CUDA. See [Running Binaries with CUDA Support](#running-binaries-with-cuda-support) for setup instructions.

**Usage:**
```bash
cargo run --release --bin transcribe -- \
  --input audio.mp3 \
  --output transcript.txt \
  --model tiny \
  --format text
```

**Arguments:**
- `--input, -i` - Input audio file (MP3, WAV, FLAC, etc.)
- `--output, -o` - Output file path (optional, prints to stdout if not specified)
- `--model, -m` - Whisper model size: tiny, tiny.en, base, base.en, small, small.en, medium, medium.en, large, large-v2, large-v3 (default: tiny)
- `--task, -t` - Task type: transcribe or translate (default: transcribe)
- `--language, -l` - Language code (e.g., en, es), auto-detect if not specified
- `--timestamps` - Include timestamps in output
- `--cpu` - Force CPU (disable GPU)
- `--format, -f` - Output format: text, json, srt (default: text)
- `--check-only` - Check system compatibility without transcribing
- `--strict` - Treat warnings as errors
- `--force` - Force execution despite warnings/errors

**Supported Models:**
- `tiny` / `tiny.en` - Fastest, ~39M params, English/English-only
- `base` / `base.en` - Fast, ~74M params, English/English-only
- `small` / `small.en` - Balanced, ~244M params, English/English-only
- `medium` / `medium.en` - Accurate, ~769M params, English/English-only
- `large` / `large-v2` / `large-v3` - Most accurate, ~1550M params, multilingual

**Output Formats:**
- `text` - Plain text transcription
- `json` - Full JSON with segments, timestamps, and metadata
- `srt` - SubRip subtitle format with timestamps

**Examples:**
```bash
# Transcribe with tiny model (fastest)
cargo run --release --bin transcribe -- \
  -i sermon.mp3 -o transcript.txt

# Transcribe with timestamps
cargo run --release --bin transcribe -- \
  -i interview.mp3 -o interview.txt --timestamps

# Generate SRT subtitles
cargo run --release --bin transcribe -- \
  -i video.mp3 -o subtitles.srt --format srt

# Use larger model for better accuracy
cargo run --release --bin transcribe -- \
  -i lecture.mp3 -o lecture.txt --model base

# Force CPU usage
cargo run --release --bin transcribe -- \
  -i audio.mp3 --cpu

# Output JSON with full metadata
cargo run --release --bin transcribe -- \
  -i speech.mp3 -o speech.json --format json

# Translate to English
cargo run --release --bin transcribe -- \
  -i spanish.mp3 -o english.txt --task translate --language es

# Check system compatibility before transcribing
cargo run --release --bin transcribe -- \
  -i audio.mp3 --model base --check-only

# Force transcription despite warnings
cargo run --release --bin transcribe -- \
  -i audio.mp3 -o transcript.txt --model medium --force

# Strict mode: exit on any warnings
cargo run --release --bin transcribe -- \
  -i audio.mp3 -o transcript.txt --strict
```

## Running Binaries with CUDA Support

Some binaries (like `transcribe`) support GPU acceleration via CUDA. You can run them with CUDA without bundling libraries by using `LD_LIBRARY_PATH`.

### Initial Setup (one-time)

Extract CUDA 12.8 runtime libraries from Docker:

```bash
cd src-tauri
docker-compose -f docker-compose.cuda.yml run --rm extract-cuda-libs
```

This creates `src-tauri/cuda-libs/` with the necessary CUDA libraries.

### Building with CUDA

Build any binary with CUDA support:

```bash
cd src-tauri

# Development build
docker-compose -f docker-compose.cuda.yml run --rm build-dev

# Release build (inside Docker)
docker-compose -f docker-compose.cuda.yml run --rm build-dev sh -c "cargo build --release --features cuda --bin transcribe"
```

Binaries are output to `src-tauri/target-cuda/debug/` or `src-tauri/target-cuda/release/`.

### Running with CUDA

Run any CUDA-enabled binary by pointing to the extracted libraries:

```bash
# From src-tauri directory
LD_LIBRARY_PATH=./cuda-libs ./target-cuda/debug/transcribe \
  --input audio.mp3 \
  --output transcript.txt \
  --model tiny

# From project root
LD_LIBRARY_PATH=./src-tauri/cuda-libs ./src-tauri/target-cuda/debug/transcribe \
  --input audio.mp3 \
  --output transcript.txt

# With absolute paths (works from anywhere)
LD_LIBRARY_PATH=/home/user/hermeneia/src-tauri/cuda-libs \
  /home/user/hermeneia/src-tauri/target-cuda/debug/transcribe \
  --input audio.mp3
```

### Simplify with Environment Variable

Add to your `~/.bashrc` or `~/.zshrc` for easier usage:

```bash
export LD_LIBRARY_PATH="$HOME/projects/Hermeneia/hermeneia/src-tauri/cuda-libs:$LD_LIBRARY_PATH"
```

Then run without specifying the library path:

```bash
./src-tauri/target-cuda/debug/transcribe --input audio.mp3
```

### CUDA Examples

```bash
# Transcribe with GPU acceleration
LD_LIBRARY_PATH=./cuda-libs ./target-cuda/debug/transcribe \
  --input sermon.mp3 \
  --output transcript.txt \
  --model base

# Check GPU compatibility before transcribing
LD_LIBRARY_PATH=./cuda-libs ./target-cuda/debug/transcribe \
  --input audio.mp3 \
  --model base \
  --check-only

# Force CPU mode (even with CUDA build)
LD_LIBRARY_PATH=./cuda-libs ./target-cuda/debug/transcribe \
  --input audio.mp3 \
  --cpu
```

### Requirements

- **Development**: NVIDIA drivers only (no CUDA toolkit installation needed)
- **GPU**: NVIDIA GPU with compute capability ≥ 7.5 (RTX 20-series or newer)
- **CUDA**: Libraries extracted from Docker (via `extract-cuda-libs` command)

### Why LD_LIBRARY_PATH?

This approach provides flexibility during development:
- CUDA libraries stay in one location (`cuda-libs/`)
- No need to copy libraries alongside each binary
- Easy to switch between CPU and CUDA builds
- Same method works for all CUDA-enabled binaries

For distribution, use `npm run build:cuda:bundle` which produces .deb, .rpm, and .AppImage packages with bundled CUDA libraries and RPATH set at link time.

## Performance Profiling Guide

### Step 1: Generate Test Files

Create test files of various sizes and formats directly:

```bash
# WAV files (various sizes and bit depths)
cargo run --release --bin generate-test-audio -- \
  -o test_small.wav -d 30 -s 44100 -c 2 -b 16

cargo run --release --bin generate-test-audio -- \
  -o test_medium.wav -d 120 -s 44100 -c 2 -b 16

cargo run --release --bin generate-test-audio -- \
  -o test_large.wav -d 300 -s 44100 -c 2 -b 16

cargo run --release --bin generate-test-audio -- \
  -o test_large_float.wav -d 300 -s 48000 -c 2 -b 32

# MP3 files (various bitrates)
cargo run --release --bin generate-test-audio -- \
  -o test_small_128k.mp3 -d 30 --mp3-bitrate 128

cargo run --release --bin generate-test-audio -- \
  -o test_medium_192k.mp3 -d 120 --mp3-bitrate 192

cargo run --release --bin generate-test-audio -- \
  -o test_large_320k.mp3 -d 300 --mp3-bitrate 320

# FLAC files (lossless compression)
cargo run --release --bin generate-test-audio -- \
  -o test_small.flac -d 30

cargo run --release --bin generate-test-audio -- \
  -o test_large.flac -d 300
```

### Step 2: Run Performance Benchmarks

Test overall performance with averaged results:

```bash
# Benchmark WAV trimming (16-bit)
cargo run --release --bin profile-trim -- \
  -i test_large.wav \
  -o trimmed.wav \
  -s 50.0 \
  -e 150.0 \
  --iterations 10

# Benchmark MP3 trimming
cargo run --release --bin profile-trim -- \
  -i test_large_320k.mp3 \
  -o trimmed.wav \
  -s 50.0 \
  -e 150.0 \
  --iterations 10

# Benchmark FLAC trimming
cargo run --release --bin profile-trim -- \
  -i test_large.flac \
  -o trimmed.wav \
  -s 50.0 \
  -e 150.0 \
  --iterations 10
```

### Step 3: Detailed Profiling

Get detailed timing breakdowns to identify bottlenecks:

```bash
# Detailed WAV profiling
cargo run --release --bin profile-trim-detailed -- \
  -i test_large.wav \
  -o detailed_output.wav \
  -s 50.0 \
  -e 150.0

# Detailed MP3 profiling
cargo run --release --bin profile-compressed-detailed -- \
  -i test_large_320k.mp3 \
  -o detailed_output.wav \
  -s 50.0 \
  -e 150.0

# Detailed FLAC profiling
cargo run --release --bin profile-compressed-detailed -- \
  -i test_large.flac \
  -o detailed_output.wav \
  -s 50.0 \
  -e 150.0
```

### Step 4: Analyze Results

Look for:
- **Time distribution** - Which operation takes the most time?
- **Throughput** - How fast is the processing in MB/s?
- **Bottlenecks** - Which step needs optimization?

## Tips for Best Performance

1. **Always use `--release` mode** - Debug builds are 10-100x slower
2. **Use larger buffer sizes** - Configured in `trim.rs` (currently 32KB)
3. **Test with realistic audio files** - Production sermons, not synthetic tones
4. **Warm up the cache** - Run once before profiling to warm up disk cache
5. **Average multiple runs** - Use `--iterations 10` for stable results
6. **Profile on target hardware** - Performance varies by CPU/SSD speed

## Troubleshooting

### "Binary not found"
Make sure you're in the `src-tauri` directory:
```bash
cd src-tauri
cargo run --release --bin <binary-name> -- <args>
```

### "File not found"
Use absolute paths or ensure you're in the correct directory:
```bash
cargo run --release --bin audio-trim -- \
  -i /full/path/to/input.mp3 \
  -o /full/path/to/output.wav \
  -s 0 -e 10
```

### Slow performance
- Make sure you're using `--release` flag
- Check if debug assertions are disabled
- Profile to find bottlenecks

### Out of memory
Reduce buffer size in `src/audio/trim.rs` if processing very large files on limited RAM systems.
